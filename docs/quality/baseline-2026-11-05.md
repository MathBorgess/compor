# Calibração inicial dos gates

Esta medição usa o código de produto do commit `7a3d50a4cd3f289b84c3e502d80e3a199e37ef87`, antes dos ajustes de entrada e conversação. Os scripts de qualidade estavam em desenvolvimento. Ela orienta o orçamento inicial e não representa aprovação do novo fluxo.

## Execução local

Foram realizadas cinco navegações sequenciais em 5 de novembro de 2026. O build era Next 16.4.4 em modo produção. O ambiente tinha Node 24.16.0, Lighthouse 13.6.0, Chrome 156, macOS ARM64 e 10 CPUs lógicas. A emulação mobile usou viewport 412 × 823, RTT de 150 ms, throughput de 1.638,4 Kbps e multiplicador de CPU 4. Esses parâmetros são simulação do Lighthouse, não características de um telefone medido.

O servidor local estava aquecido pelo GET de prontidão. Cada navegação usou o reset padrão do Lighthouse, dentro do mesmo perfil temporário. Outros testes locais estavam ativos, portanto os números incluem possível contenção do host. Não houve comparação de velocidade entre implementações.

| Medida | Mínimo | Mediana | Máximo |
| --- | --- | --- | --- |
| LCP | 903,39 ms | 910,81 ms | 921,97 ms |
| TBT | 13,00 ms | 17,00 ms | 30,70 ms |
| CLS | 0 | 0 | 0 |
| Trabalho total da thread principal | 283,06 ms | 307,28 ms | 320,19 ms |
| Inicialização de JavaScript | 127,29 ms | 144,51 ms | 151,66 ms |

A coleta **falhou** no gate de integridade porque a primeira navegação registrou `/favicon.ico` com HTTP 404 no console. Os números acima são diagnósticos desse conjunto rejeitado. O gate não ignora essa falha para produzir uma aprovação. Uma nova coleta da interface integrada precisa validar o ícone e registrar seus próprios resultados.

O HTML inicial referenciou **216.816 bytes gzip** de JavaScript. Todos os chunks somaram **217.097 bytes gzip**. O orçamento inicial de 250.000 bytes deixa 33.184 bytes para mudanças pequenas na entrada. O teto total de 300.000 bytes permite componentes opcionais sem tornar o crescimento do cliente invisível. São limites de projeto revisáveis, não resultados de uma otimização.

O diagnóstico mostra pouco tempo bloqueante nessa entrada sem sessão. A inicialização de JavaScript ocupa parte relevante do trabalho da thread principal, mas a coleta não identifica um gargalo de usuários reais. Os dados não justificam alegar melhora de geração, conversação autenticada ou throughput de APIs.
