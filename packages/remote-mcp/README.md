# MCP remoto — fronteira inicial

Este pacote fornece um handler HTTP stateless para integrar a uma rota Node.js do backend. A credencial `Bearer` é verificada em cada requisição pelo Supabase Auth configurado pelo servidor; sem autenticador, a fronteira falha fechada. A ferramenta `prepare_brief` organiza dados fornecidos sem persistir nem confirmar fatos ou preferências. Quando configurado explicitamente um `projectStore`, as ferramentas `create_project` e `list_projects` criam e listam projetos privados.

`createSupabaseAuthenticator` recebe URL HTTPS do projeto e chave pública (anon/publishable), nunca chave administrativa. `createRemoteMcpHandler` recebe o autenticador e devolve função `(Request) => Promise<Response>`. Um provedor de identidade indisponível retorna 503, sem ecoar credenciais; requisições são limitadas a 64 KiB e não são armazenadas em cache. Testes usam o transporte HTTP do SDK MCP e simulam serviços externos de identidade e dados.

`createSupabaseProjectStore` recebe URL HTTPS e chave pública, e acessa PostgREST com o token do usuário verificado. A migração `supabase/migrations/20261103000000_projects.sql` define acesso mínimo e políticas RLS para projetos. Os testes de projeto simulam PostgREST e suas políticas; portanto **não comprovam RLS** nem foram executados contra um banco real. Aplique a migração somente após revisão e teste de isolamento em ambiente Supabase isolado.

`createSupabasePieceStore` disponibiliza versões de peça com texto, preço, data e legenda com origem. `save_piece_version` recebe um projeto, um identificador de peça, a versão esperada (zero para criar) e o conteúdo integral: devolve `saved`, `conflict` com a versão atual ou `not_found` para projeto inexistente ou alheio. `list_piece_versions` consulta o histórico. A migração `20261103000001_piece_versions.sql` define versões imutáveis e RLS; sua função de gravação verifica propriedade e usa bloqueio do projeto para serializar operações. Usuários autenticados não têm permissão de inserir diretamente na tabela. Em falha de comunicação após o envio, consulte o histórico antes de tentar novamente: o resultado da gravação pode ser desconhecido. Matheus [relatou](../../docs/spikes/2026-11-03-supabase-rls-validacao.md) execução transacional em Supabase isolado com rollback; o agente não capturou a saída completa. Os testes simulados não comprovam isolamento em produção nem concorrência entre conexões PostgreSQL.

`list_pieces` permite ao Codex descobrir peças em um projeto autenticado. Aceita `projectId` e opcionalmente `after`, um UUID obtido como `nextCursor`; retorna até 50 peças, com ID, versão mais recente, título e data, e `nextCursor` ou `null`. Continue até o cursor ser nulo: toda página não vazia retorna um cursor e a última consulta é vazia, pois o PostgREST pode impor um limite de linhas menor que o solicitado. O PostgREST consulta até 101 versões por vez, ordenadas por ID da peça e versão decrescente, com filtro de dono e o JWT da pessoa; o adaptador valida o dono e o projeto de cada linha. Mesmo quando uma peça tem mais de 101 versões, a primeira linha é sua versão mais recente, e avançar pelo ID dessa peça não salta a peça seguinte. Projeto vazio ou sem acesso retorna lista vazia. A consulta não é um snapshot: uma peça adicionada antes do cursor durante a paginação só aparece após reiniciar a listagem. Nenhuma migração nova é necessária. Os testes usam PostgREST simulado; ainda é necessário provar paginação e isolamento com o banco real.

```sh
npm ci
npm test
```

O aplicativo Next.js já inclui a rota `/api/mcp`, os adaptadores de projetos e peças e um corte experimental de OAuth/discovery desativado por padrão; veja [apps/web](../../apps/web/README.md). O pacote não implementa Storage, observabilidade operacional ou geração de imagem. A prova sintética separada da OpenAI não conectou o Compor; OAuth, Codex Desktop, Supabase e Vercel não tiveram a jornada integrada verificada. Não expor o endpoint até as fronteiras pendentes serem verificadas. O token MCP é distinto da chave OpenAI BYOK.

## Delegação experimental para Agents API

`@compor/remote-mcp/agent-scope` contém uma fronteira interna ainda **sem rota ou integração com o produto**. Ela emite uma credencial delegada, cifrada e autenticada com AES-256-GCM, válida por até cinco minutos, somente após autenticar o JWT Supabase e consultar a titularidade do projeto por dependências confiáveis. O envelope contém conta, projeto e JWT; apenas o backend detentor da chave o abre, revalida o JWT a cada pedido e verifica novamente a titularidade antes de cada leitura ou gravação de peça. Não oferece listagem ou criação de projetos. Esse isolamento depende de callbacks reais, de RLS e da confidencialidade da chave; os testes são simulados. O envelope é uma credencial bearer reutilizável até expirar: quem o obtiver pode operar dentro do escopo, portanto nunca registrá-lo. Ele não altera os privilégios do JWT original em outras superfícies.

`withAgentMcpTool` entrega a configuração efêmera de `agent.tools` a um callback interno de envio; ela não devolve a credencial no resultado, não deve ser usada com entrada de cliente como origem e captura erros sem expor detalhes. O callback precisa construir e enviar a sessão sem registrar o objeto, a chave OpenAI, o token ou os cabeçalhos, e guardar apenas uma resposta sanitizada; exceção após invocação é resultado desconhecido, sem repetição automática. O campo `required` não comprova que o MCP foi inicializado. O destino deriva da origem HTTPS fixa de configuração para `/api/agent-mcp`; a validação rejeita endereços IP e nomes locais, mas não garante resolução DNS pública, nem substitui controle da origem e implantação confiáveis.

Antes de habilitar: revisão independente de criptografia e autorização; implementar a rota separada e configurar chave aleatória de exatamente 32 bytes exclusiva por ambiente no servidor. O domínio é separado por AAD fixo; perda ou rotação da chave invalida envelopes anteriores. Planejar rotação, interrupções e reconciliação; conectar emissão apenas depois de autenticação e verificação de projeto e exigir RLS. A OpenAI recebe apenas o envelope opaco na autorização transitória. A expiração de cinco minutos pode ocorrer durante um turno; uma solução de renovação precisa reautorizar e atualizar a sessão de maneira segura, sem retry automático nem presumir que o turno falhou. Não reutilizar a rota OAuth independente do Codex para contornar essas garantias. Verificar com duas contas reais, revogação, uso cruzado, expiração e concorrência; inspecionar o comportamento real da Agents API e OAuth/Codex antes da exposição. Fonte: [MCP connections na Agents API](https://developers.openai.com/api/docs/guides/agents-api/tools/mcp).

A fronteira contra SSRF depende de `appOrigin` ser uma origem fixa e confiável de configuração do servidor. Nunca derive esse valor de cabeçalhos `Host`, `Forwarded` ou de parâmetros da requisição. A validação sintática não consulta DNS e não impede que um domínio permitido resolva para endereço privado ou mude de resolução; a implantação deve controlar o domínio e as regras de rede, e comprovar o transporte real antes de habilitar a delegação.
